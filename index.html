"페르소나를 기본적으로 부캐라고 이야기하지만 말의 구조, 뽐새거든요. 그 후킹 방향을 어떻게 잡느냐에 따라 같은 영상·사진을 올려도 유입률이 달라져요." — 9/2

  • 다계정 운영 시 텍스트와 콘텐츠까지 똑같이 올리면 안 된다. 계정마다 페르소나를 달리한다.
    "텍스트랑 컨텐츠까지 똑같이 올리면 바보입니다. 이때 페르소나 테스트를 하세요. 어떤 후킹이 잘 먹히나. 잘 터지는 페르소나를 빠르게."
  • 해시태그는 의미 없음.
  • 계정 컨셉과 안 맞는 콘텐츠는 올리지 않는다. (본인 개발자 계정에 쇼핑 콘텐츠를 안 올리는 이유로 설명)

  2. 프로필에 안 들어가지는 현상 → 다른 아이디로 검색해서 안 나오면 비활성화

  • 드레쓰는 메타 승인 심사를 받고 만든 툴이라 다른 카톡방 툴과 다르다는 게 본인 주장.

1-6. 조회수 해석 — 방에서 가장 많이 나온 질문

핵심

"조회수 0이라는 건 없어요." 스레드 조회수는 오류가 잦아 안 보일 때가 많다.
안 보일 때 추정법 → 타래 조회수 × 2~5배 = 본문 게시물 조회수 (9/14 재언급, 기존 2~4배에서 소폭 조정)

  • 내 화면엔 안 보이는데 남에겐 보이는 오류도 있다.
  • 3자리도 전환은 된다. 4자리 나오면 "음 나오네" 정도.
  • 레퍼런스로 가져올 기준: 좋아요 200개 정도 보이면 가져간다.
  • "글 올리고 조회수 올라라올라라 하고 바라보고 있진 마세요."
  • 계정이 많아지면 매번 조회수 확인 안 한다. 계정이 몇 개 안 되니까 자꾸 보는 것.

1-8. 드레쓰(툴) 세팅 — 개발의신 + CS 공식 답변

가장 많이 막힌 지점

GPT · 제미나이 "구독"과 "API"는 완전히 별개다. API는 사용량 과금(주로 선불 충전)이라 충전 잔액이 없으면 기능하지 않는다. 이걸 헷갈린 참가자가 압도적으로 많았다.

  • 챌린지 신청 시 쓴 아이디/비번 그대로 로그인하면 자동 연동. 드레쓰 별도 가입 불필요.
  • 드레쓰 로그인 = 툴 로그인일 뿐. 여기에 스레드 계정을 따로 연동해야 글이 올라간다.
  • 크롬 확장 연동: 드레쓰 → 벤치마킹 보관함 → 키 발급하기(JWT) → 크롬 확장 DReaThs Scraper에 붙여넣기. 확장은 크롬 프로필별로 각각 설치 가능.
  • 실시간 구글검색 활용은 off가 정상.
    "왜냐? 유료 API만 되거든!!!! 무료면 안 된다는 오류 알림이 나옵니다."
  • AI API: 제미나이 무료 API가 편하다. 단 "무료는 오류가 생각보다 많아요."
  • "네트워크 오류" 대표 원인 (CS 개발팀 확인) — GPT 이미지 분석 실패 → 제미나이로 재시도 → 제미나이 API 키 없음 → 팝업. 이미지 분석 토글을 끄면 해결.
  • 마이페이지에서: 글양식 설정 / 토스 이미지 on-off / 대표 아이디 설정 / 활동채널 추가.
  • 홈페이지 502는 업데이트 중이라는 뜻 → 새로고침. 확장은 업데이트마다 껐다 켜야 함(하루 5회 이상 업데이트).
  • 링크 미리보기 축은 드레쓰에서 랜덤. 없앨 수 없고, 있는 게 좋다는 게 공식 답변.

Section 2

참가자들이 실제로 검증한 팁

신뢰도

이 절은 주인장 발언이 아니라 참가자 경험담이다. 그만큼 낮게 잡고 봐야 한다.

다계정 세팅

  • 크롬 프로필 분리가 사실상 표준 방법. 크롬 우상단 프로필 → Chrome 프로필 추가 → 프로필마다 다른 구글 계정 → 각 프로필에 스레드 계정 로그인 유지.
  • 구글 계정은 전화번호 없이 생성. 단 며칠 안에 여러 개를 몰아서 만들면 스팸으로 감지돼 막힌다.
  • 인스타 1개 : 스레드 1개. 인스타를 새로 만들었으면 인스타에 들어가서 스레드를 생성해줘야 한다.
  • 스레드 계정 추가 등록은 한 번에 여러 개 말고 시간을 두고. (CS 공식)
  • 인증 문자가 안 오면 왓츠앱으로 인증. (CS 공식)
  • 공기계는 불필요하다는 게 다수 의견.

스레드 플랫폼 제약

  • 스레드 수정은 15분 이내만 가능. 이미지·영상은 수정 불가. (개발의신)
  • 스레드 예약은 25개 내외가 한도. (실측)
  • 링크 미리보기 이미지는 스레드 앱/웹에서 X버튼으로 제거 가능. 단 게시 전에만. 드레쓰가 아니라 스레드 자체 기능.

글쓰기 — 방에서 반응이 가장 좋았던 조언

핵심 4가지
  • 내가 팔고 싶은 상품을 팔지 말고, 터진 글을 먼저 찾아 재가공하고 타래에 관련 상품 링크를 넣어라.
  • 후킹은 3~4줄 안에 끝내고, 첫 줄에 다 때려넣어라. 구구절절하면 안 된다.
  • 후킹 세기가 부족한 경우가 대부분. "더 세게, 더 짧게."
  • 일상글은 댓글 유도형으로. "나 2년째 고민 중인데 이거 어때?" → 댓글이 붙는다.
  • 이슈글 재가공이 잘 터진다.
  • 타래 공정위 문구 아래 한 줄이면 어떤 상품이든 연관시킬 수 있다.
  • 조회수 기준(개인 기준): 1만회 = 터진 것 / 1천 = 무난. 1만은 넘어야 1만원이라도 나온다.
  • 마지막에 클릭한 링크의 쿠키가 잡힌다 → 내 계정·내 글을 여기저기 많이 걸쳐놓는 게 유리. "낚싯대를 마구마구".

성과 후기

전부 개인 주장 · 미확인
  • AI 영상 게시물 조회수 11만 / 20만 — 댓글은 "AI다"라며 부정적이지만 조회수는 나옴.
  • 일상글 소재로 빌런 이야기 · 시댁 이야기가 조회수·답글 폭발.
  • 첫 글 조회수 7천 / 자고 일어나니 5천·좋아요 200·댓글 13 사례.
  • 예약만 걸고 신경 안 쓰니 수익 발생. 팔로워 늘린다고 돌아다니면 정지당한다는 후기.
  • 조회수 ≠ 전환. 몇만 조회에 다음날 클릭 1건인 사례도 있었다.
  • 토스가 조회수 대비 전환율이 좋다는 지인 전언.
  • 다수 참가자가 1주차에 계정 비활성화·영구정지를 겪음. 재생성해서 재시작이 일반적 대응.
  • 매출 실적·그래프를 블로그 등에 자랑하면 경고·정지 위험.

내가 스레드 운영에 적용한다면

주인장 발언 중 바로 실행 가능한 것만 추린 순서다. (정리자 판단)

  1. 벤치마킹 전용 계정 1개를 먼저 만든다. 여기서만 스크랩하고, 발행은 다른 계정에서 한다.
  2. 레퍼런스 계정 링크를 몇 개 클릭해 추천 피드를 오염시킨다. 콘텐츠 소싱 시간이 여기서 줄어든다.
  3. 영상 → 상품 순서를 지킨다. 상품에서 출발하면 느리다.
  4. 후킹 문장 구조를 페르소나로 고정한다. 매번 손으로 쓰면 지속이 안 된다. 페르소나를 여러 개 만들어 A/B로 돌린다.
  5. 1주일은 조회수를 판단 근거로 쓰지 않는다. 1~2자리가 일주일 지속될 때만 계정을 바꾼다.
  6. 터지면 바로 링크를 붙인다. 그 타이밍을 놓치지 않는 게 수익화의 전부다.
  7. 계정은 죽어도 버리지 않고 보관한다. 2달 뒤 재시도 여지가 있다.

Section 4

주의해야 할 부분

쿠파스 15만원 실적 만들기

콘텐츠 재가공

남의 게시물·영상을 스크랩해 재가공하는 방식이 기본 워크플로우다. 주인장도 "이미 남의 것을 가져가는 게 위반"이라고 언급했다. 저작권·플랫폼 정책 리스크가 있다.

수치의 신뢰도

이 문서의 수익·조회수 수치는 전부 참가자 자기보고다. 광고 성과 자료로 인용하면 안 된다.
